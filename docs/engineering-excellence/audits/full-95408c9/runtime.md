# Runtime findings and acceptance tests

All paths and line numbers refer to `95408c9`. F01–F04 are in the [audit overview](README.md). The two small programs beside this report use the published core API and leave the workspace test counts alone.

## Simulation, spatial queries and saves

**F05 · High · A legal collider edit makes the collision query miss.** `crates/engine-core/src/collision.rs:57–76` exposes the center, half-extents and yaw for writing. Its frame and world bounds are private cached values. `to_local` at 148 uses the current center and cached frame. `overlaps_box` at 207 rejects against the old bounds before reaching the narrow phase. `player.rs:679–703` can also build the static grid from those old bounds. In [the external consumer witness](collider_witness.rs), translating a unit box to x=10 leaves its bounds at [-1,1]. A box built directly at x=10 reports an overlap at the same query, while the translated one reports a miss. Both programs use safe public operations. Make geometry fields private with read accessors and provide validated whole-value replacement for movement/resizing. Verify individual field changes, reconstruction, and below/above-grid-threshold query equivalence. Also reject unrepresentable derived bounds at construction: lines 86–109 validate the inputs but calculate the corners and Y extents afterward.

**F06 · High · An in-memory NPC section passes validation and fails its own restore.** A full-LOD region with one NPC on a four-cell grid is sufficient. `crates/engine-core/src/npc_world_save.rs:588–596` rejects a non-sentinel off-grid position on restore. Lines 657–718 validate column lengths and durable home cells but never inspect these active positions. Lines 449–456 write them. The [one-NPC witness](position_witness.rs) round-trips (0,0). For (4,0), validation succeeds and restore returns `npc-world-save-v2/position-bounds`. Share the position predicate between the constructor validator and decoder. Add ordinary cell, exact edge, discard sentinel and partial-sentinel cases. Give public callers a fallible validated encoding path while preserving existing valid bytes. This is independent of the resource admission issue F02.

**F07 · High · History compaction relies on the caller to establish consequence eligibility (Q05).** `crates/engine-core/src/spine.rs:1913,2018–2019,2058–2070` accepts a policy and summarizes a chunk when a length threshold fires. `compact` at 1977–2006 hashes the prefix then copies the entire retained tail through `split_off`. Restore at 3208 clears runtime retention configuration, an intentional contract covered at 5003–5007. Neither cadence nor reconfiguration proves all consequence consumers can relinquish that prefix. Introduce an acknowledged safe cut at the composition boundary, expose refusal/lag, and persist or reapply the runtime policy separately from canonical world bytes. Pin restore → reconfigure → next compact against an uninterrupted control with unresolved consequences. Measure bytes moved and worst tick as retained history grows at constant chunk size.

**F08 · Medium · Regional transitions still depend on the entire queue (A08).** `spine.rs:1752–1822` processes queues through an ordered sort and extraction. Ordering is required for the public stateful predicate. An index for known region/identity transitions can coexist with that general API. Maintain membership on every schedule, hold, release and restoration. Compare predicate visit order and canonical bytes for the generic path. For the indexed path keep affected work fixed while growing unrelated population and measure both update and query work.

**F09 · Medium · The indexed query APIs need a production adoption boundary (Q04/Q09).** `crates/engine-core/src/npc_perception.rs:438–465,611–641` has reusable scratch, an admission heuristic and an ordered candidate pass. `combat.rs:842–850` borrows the roster it indexes. The live combat path in `crates/engine-slice/src/combat_demo.rs:966` calls the linear resolver. Retain the tiny-roster path. Build once per stable roster/epoch only when the number of queries pays for the build. At the actual caller compare tie ordering, results, allocations, update overhead and dense/long-ray fallback at increasing sizes. The existence of a microbenchmark alone does not establish frame savings.

## Renderer and shaders

**F10 · High · A post-acquire error can strand a frame slot.** `crates/engine-renderer/src/vulkan/frame.rs:574–627,826–847,1546–1550` assigns the image a fence and resets the slot fence before upload, semaphore acquisition, command recording and submit have succeeded. Those operations are fallible. If the function returns before a successful submission, no work owns the reset fence. The next call waits on the same slot at 712; the timeout is two seconds (`vulkan.rs:186`). The acquired image and its signaled acquire semaphore also need an explicit disposition. Defer the reset until submit, publish per-image ownership only after success and define a recovery or terminal state for every error after acquire, including submit failure. Inject error outcomes at all four boundaries and verify immediate retry/recreate or typed terminal refusal; keep semaphore validation and resource balances on the real GPU.

**F11 · High · All three arena growth paths can lose newly allocated handles on a failed wait.** The region replacement allocates/maps at `vulkan/pipelines.rs:281–288`, the proxy at `vulkan/passes/proxy_draw.rs:505–520`, and the pose buffer at `vulkan/passes/skinned_draw.rs:255–267`. The fallible idle wait precedes ownership transfer. The returned tuple from `vulkan/resources.rs:241–289` has no destructor. The helper cleans up failures *inside* construction, but its successfully returned objects have no local cleanup on these returns. Put the replacement in a scoped owner while it is unpublished. Cover an injected idle failure after successful allocation and before old-buffer retirement in each path. Validate old bindings and new-object cleanup, including the device-loss disposal policy.

**F12 · High · Configuration and arena growth use different integer domains.** Instance and pose budgets are public `usize` values (`config.rs:157,171`). CPU pack admission reads those values (`renderer.rs:828–841`), while device carving narrows them to `u32` (`vulkan/pipelines.rs:347`, `vulkan/context.rs:832,851`). The growth helper at `config.rs:387–392` rounds up before clamping, and the next power of two need not fit the type. Validate a shared representable capacity at construction; include device limits, per-slot sizes and dynamic-offset alignment. Use checked growth, capped at a validated maximum. Test pure planning at zero, floor, non-power-of-two caps and representability edges in debug and release. Validate admitted counts against the actual physical carve before upload.

**F13 · High · Device loss is flattened at the public error boundary (A14).** `vulkan.rs:191–242` has typed capture/packing errors and converts generic Vulkan results to formatted strings. `vulkan/frame.rs:1590–1602` explicitly handles out-of-date presentation, so the earlier blanket claim that *every* Vulkan outcome is flattened is too broad. Introduce a device-loss variant carrying operation context, latch it across frame/attach/upload, and prevent repeated submissions on that device. Test result classification and subsequent calls via fault injection. Real device removal remains a separate validation question.

**F14 · Medium · The public scene contract still encodes the first pass family's assets (Q06/R06).** `scene_description.rs:95,145,222–229,333–342` sets a fixed material count, reflection range shape and texture byte size. The garage proves reuse inside that family. Introduce clearly typed texture extents and material/draw tables at admission, then negotiate per-pass resources. Preserve the approved full-resolution reflection default. Add a second *resource topology* with different counts and dimensions, invalid role/range cases, switch/release tests and matched captures.

**F15 · Medium · Triangle-list boundaries can disagree between passes.** `scene_description.rs:247,286–319,396–424` checks ordering, coverage and bounds, but does not check triangle-aligned boundaries for draws, receiver or reflected ranges. A split inside a triangle is accepted by these checks; drawing the whole buffer and drawing separate material ranges can assemble different primitive sets. Verify the primitive topology at each consuming draw, reject incomplete triangles when admitting that topology, and test a contiguous but misaligned range next to a valid three-vertex boundary. Keep exact color/depth agreement on the valid case.

## Persistence and recovery

**F16 · High · The feature-gated crash/reclaim integration suite does not compile.** `crates/engine-slice/tests/pp_b3_reclaim.rs:32–33` imports two arming statics from `engine_persist::local`. The implementation is in private `local::reclaim_exec` (`crates/engine-persist/src/local.rs:76`, `local/reclaim_exec.rs:1160–1162,1187–1189`). The feature is already forwarded by `crates/engine-slice/Cargo.toml:19`. The exact CI heavy command exited **101 (E0432)**, before any test ran. Restore the two existing names at the facade under the same feature. Run the complete crash-seam suite, check the default build still excludes the seam and measure exact counts before any integration-side pin correction.

**F17 · Medium · The settled watermark bounds scanning, while confirmed identity storage still grows with history (Q08).** `crates/engine-persist/src/pipeline.rs:779–799,811–826,2041–2058` frees coverage vectors beyond the window but keeps confirmed entries and a separate set of shed IDs. `confirmed_evidence` at 1488–1502 walks the map and clones retained coverage. Design authenticated cold membership/producer retrieval before evicting metadata; preserve duplicate detection, retry identity and provenance across both providers. Measure resident bytes and cold lookup latency with fixed live obligations over growing histories. Test partial settlement, crash/reopen, missing history and a query across the eviction boundary.

**F18 · Medium · Backup still materializes the complete journal for hashing.** `crates/engine-slice/src/backup.rs:447–455,479,487–490,574–598` reads the journal into a vector on capture and again during mandatory verification, alongside scans for the last committed transaction. `crates/engine-persist/src/journal.rs:258–276` reserves the file size. The streaming replay work does not remove this separate whole-file consumer. Stream the same byte hash and length through a bounded buffer, retaining all journal and recovery verification. Compare manifest hashes, truncation behavior and peak RSS at growing journal lengths with identical content.

**F19 · Medium · SQLite backup uses two path representations.** `crates/engine-persist/src/sqlite/backup.rs:42–56` passes a lossy string to `VACUUM INTO`, then opens the original native path. On platforms with non-Unicode paths these can identify different files. Define and enforce a lossless path contract before creating output, or use a native SQLite backup interface that accepts an open destination connection. Test a disposable platform-appropriate non-Unicode target; ensure a refusal leaves no sibling file under a substituted name. Current evidence is the two different conversions in source.

**F20 · Medium · Backup completion and power-loss durability have different evidence.** `crates/engine-slice/src/backup.rs:438–444,709–720` copies the journal, syncs the temporary manifest and renames it; failure to sync the destination directory is ignored. Immediate scratch recovery at 686–706 establishes usability in the running system. Publish the precise durability tier. For a power-loss promise sync required artifacts and propagate/classify directory-sync failure per platform before reporting durable completion. Use injected sync failures and disposable restart tests. The existing live-readback check remains valuable.

## Shell and input

**F21 · Medium · A bounded audio ring still has unbounded producer lock work.** `crates/engine-shell/src/audio.rs:771–786` holds the command lock while traversing the entire input slice. Every rejected item performs a separate atomic increment once the ring is full. The callback's nonblocking `try_lock` at 930 can defer the entire batch. Copy only the admitted prefix, account for the rejected tail with one addition, then release the lock. Test FIFO/listener pairing, identical refused count and lock-held operations as caller batch length grows past ring capacity. The bounded callback copy and voice starts after unlock at 930–942 are sound.

**F22 · Medium · The legacy cue stream lacks the device mixer's backpressure (NEW-SHELL-1/3).** `audio.rs:311–323` enqueues a complete sample per call and handles SDL write errors. There is no queued-byte limit in this surface. Either route cues through bounded mixer voices or add an explicit queue budget and refusal telemetry. Compare audible ordering, startup/resident PCM, overload response and real-device behavior before consolidating the two public surfaces.

**F23 · Low · Scancode-only repeats do affect the snapshot.** `crates/engine-shell/src/input.rs:20–24` says keycode-less events are silently dropped. At 139–147 the repeat branch increments before checking the keycode. Specify whether repeats are a raw event count or count only mapped keys, then align the documentation and test one mapped repeat, one unmapped repeat and an ordinary unmapped press. The current mapping and B08 memory reuse are independent.

## Repeating the two core witnesses

From a worktree at the audited revision, run `cargo build -p engine-core`. Find its `libengine_core-*.rlib` under `target/debug/deps`. For each witness, run `rustc --edition=2024 -L dependency=target/debug/deps --extern engine_core=<rlib> <witness.rs> -o <executable>`, then run the executable. On Windows both compilations exited 0 and each program exited 101 on the final equality assertion. These are ordinary public-API correctness probes. No storage or GPU services are required.
