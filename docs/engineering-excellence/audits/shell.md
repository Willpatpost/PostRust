### Threading map (what runs where)

- **Main thread (single):** everything in `ShellApp` (window, pump, input, pacing loop), the cue-surface `Audio::play` pushes, `AudioDevice::submit_triggers` (producer, blocking lock).
- **SDL audio thread (one):** `MixerCore::run_callback` → `drain_commands` (try-lock) → voice starts → chunked `render_chunk` → `put_data_i16` sink. Bounded work: ≤ ring (256) voice starts + ≤ requested/2048 chunk iterations; no Rust allocation on the success path (measured); no blocking (deferred drain instead).
- **SDL-internal (outside Rust):** stream-conversion copies for the cue surface's push streams (unbounded input queue — NEW-SHELL-1).

### Preserved strengths verified (no violations found)

- **Vendored-static SDL3 linkage**: `sdl3 = 0.20, default-features = false, features = ["build-from-source-static"]` + target-scoped `sdl3-sys` unix console-build feature (Cargo.toml:20–29); pinned by the version test. No system SDL anywhere in the manifest.
- **Callback discipline**: allocation-free audio-thread body (measured in-crate through the identical body + counting seam, including `realloc` counting per finding-22 corrective), try-lock deferral, bounded chunks, fail-visible counters, honest statement of the one SDL-side failure-path allocation.
- **Zero project-owned unsafe** in shipped code (workspace `unsafe_code = "deny"`, root Cargo.toml:18; the single `unsafe impl GlobalAlloc` is `#[cfg(test)]`-scoped with a documented SAFETY argument).
- **Event-driven, presentation-consumer audio**: no per-frame audio API on the device layer; deterministic headless paths never construct these types; no audio state in authoritative state.

## Unexamined / limitations

**Unexamined (outside `crates/engine-shell`, listed for honesty):**
- `engine-core/src/audio_synth.rs` synthesis *algorithms* beyond the length pins (3,840 / 96,000 samples) and seeds — its quality is the core auditor's area; this audit only consumed its contracts.
- Vendored SDL 3.4.18 internals beyond the targeted claims verified for this audit (hint strings, `SDL_Quit`→`SDL_QuitHints`, `SdlDrop`→`SDL_Quit`, `SDL_DestroyWindow` magic-check no-op, `SDL_PutAudioStreamData` no-cap). A full read of `PutAudioStreamBufferInternal`'s queue representation was not done; NEW-SHELL-1 is worded accordingly (no cap found at the public entry; queue is SDL-owned either way).
- `engine-slice` consumers were read only as far as needed to trace B08's accumulator lifecycle and A25's caller (`corner_demo`'s tick-path `submit_triggers`) — that crate is another auditor's area.

**Limitations:**
- Static analysis only: no build, no test execution, no hardware audio. "Zero allocations on the audio-thread success path" is the crate's own measured claim (in-file counting seam) plus static confirmation that every path in `run_callback`/`drain_commands`/`start_voice`/`render_chunk` touches only preallocated buffers — I verified the code paths, I did not re-run the measurement.
- Byte sizes (32 B `Voice`, 72 B `QueuedSound`, 28 B `SoundTrigger`, 44 B `Listener`, ~434 KiB / ~326 KiB totals) are derived from Rust layout rules on the verified field types, not from executed `size_of`; expect ±padding rounding, not order-of-magnitude error.
- A25/B08 severities are structural judgments; the charter's own disposition ("measure rather than assuming") means the P0 baseline battery should confirm the practical cost before the P1 fix.
