## 2. Preserve the genuine gains

The following are materially useful changes. Do not revert them merely because they need further hardening.

1. Static/combat grids now route objects covering more than 64 cells (including checked multiplication overflow) into an oversized list rather than allocating every cell. CombatIndex borrows the roster. Rotated collider geometry is corrected through validated ownership per Codex F05. The old same-length-roster problem is removed at the API shape. Preserve linear fast paths and canonical result ordering.
2. NPC section decoding has cumulative identity-budget checks, minimum encoded-width checks, fallible column reservations, configurable limits; in-memory positions and restore have a shared validation direction. These are large improvements over the original count-only gate.
3. Class-aware scheduling avoids scanning unrelated held entries when the class index exists, and avoids touching an empty membership queue. Production region composition uses the class-specific API. Keep arbitrary stateful predicate ordering canonical. Do not mislabel the remaining heap walk as localized.
4. The retention policy now requires explicit application eligibility acknowledgment and reports lag/refusal for an unarmed bound. In-place drain removes allocation/reallocation from the old split-off path. Neither is a moving authorization frontier by itself.
5. Shared `chain_walk.rs` removes duplicate provider walk logic; differential battery was built first according to commits `2ecadf5`, `59aec7e`. `Arc<[u8]>` composite payload sharing and previous streaming journal improvements remain.
6. Persistence cold membership/provenance retrieval and residency census have been added; backup hashing streams; native SQLite backup replaces lossy path conversion; backup completion reports durability. These improve correctness and observability; hot eviction is not yet implemented.
7. SQLite feature isolation is implemented (`P/../Cargo.toml` default `sqlite`, optional `rusqlite`, typed not-built refusal). SDL wrapper/sys exact requirements are implemented as reported in the new footprint record. Retain default functionality and deliberate native dependency upgrades.
8. Renderer demand-sized arenas, configurable typed capacities and scoped replacement guards are meaningful. Reported E-15: corner/garage instance two-slot mapped storage falls from 786,432 to 12,288 B, poses from 5,767,168 to 90,112 B at their admitted demand. These are specific buffers, not total VRAM.
9. P5 generation-aware packing, per-slot stamps, shared rest pose and dense pose mapping are meaningful reductions in between-tick copying. The corrective rig wave found real palette changes and obsolete expectations, then rebaselined them. Retain exact per-instance pose mapping proofs; do not credit a changed pin alone.
10. Staging pool and batched deferred scene upload reduced reported submits from five to two; permanent per-texture staging tails removed. It adds a shared pool, so net residency must be compared, not just the texture counter.
11. Ripple field outer extent early-out avoids testing all rings outside their common coverage. Preserve conservative no-false-negative behavior. Shared depth target uses one image per frame slot across wet/HDR depth passes, rather than unsafe multiple-image memory aliasing. Reported 7,372,800 B at 720p through 66,355,200 B at 4K savings for the depth pair; leave color aliasing measurement-gated. Full-resolution reflection still default.
12. Scene/pipeline rollback guards, delayed slot-fence commit, typed device loss, checked arena integer domains and triangle-aligned *static* DrawTable are constructive. Inspect interactions with R3/R2 rather than assuming those earlier corrections cover later changes.
13. Shell input buffer reuse, audio lock narrowing, cue backpressure and mapped-key repeat behavior are sensible. Prior frame interval bounding remains valuable.

### T02 — Generation stamp invalidation is too late on interrupted preparation (strong source-derived hypothesis, S0; A18/CA11)

**Evidence:** `R/vulkan/frame.rs:599–657,650–705` snapshots `ctx.arena_growth_events` at entry, performs fallible `prepare_frame`, waits the slot, acquires/retries, returns on Deferred, and only then clears `frames.population_stamps` if the counter changed *during that invocation*. `R/frame_prepare.rs:153–204` calls the ensure ladder, then may recreate or run other fallible operations. `R/vulkan/pipelines.rs:753–805` can grow instances, then fail growing poses or creating indirect/shadow/etc. `R/vulkan/passes/proxy_draw.rs:546–600` commits a new empty mapped instance buffer and increments the counter. On a successful replacement followed by a later error or deferred acquire, the clearing site may never run. Next call takes the newer counter as baseline, and old generation stamps can falsely vouch for empty replacement storage. This also disproves the comment that a local baseline delta automatically carries a previous frame's unreported growth to the next frame. Need trace all recreation paths before claiming every variant is affected.

**Repro:** warm both slots at nonzero generation g; force one arena replacement without changing the relevant population's version (e.g. change another required resource, or orchestrate generation g that a slot already held, then grow after a previous failed/deferred preparation). More direct isolation: populate stamp at g, inject instance growth then a downstream failure; retry with g for a reused slot or a valid scenario in which a particular buffer's stamp remains equal after replacement; a growth of an instance buffer generally coincides with changed count/version, so ensure the witness distinguishes invalidation failure from caller misuse. A pose arena can grow on a changed population while instance gen remains unchanged, and vice versa; inspect all exact reachable combinations, including same generation reused after a higher demand frame that never reaches upload. Test successful growth followed by failed later ensure/acquire, swapchain recreation, generation-zero transition, new indirect resources, and retry across both slots. If the current legal inputs cannot exhibit a stale skip in a particular case, record the proof and still eliminate delayed invalidation as a fragile invariant.

**Solution:** bind stamps to the actual resource allocation epoch/identity, not a local counter delta. At the moment of resource publication, invalidate that resource's slot stamps or increment its epoch. Every skip checks `(resource_epoch, producer_identity, content_version, relevant shape)`; resource creation, replacement and reset cannot inherit previous resource identity. Store last-reported cumulative counter persistently if reporting per-frame deltas; separate diagnostic from correctness. A transaction-like preparation API can return explicit replacement events even on later errors, but resource-owned epochs are stronger and simpler. Tests should check actual mapped bytes or readback/indirect draws against always-upload oracle after every injected boundary. Do not insert global idle waits as a substitute for identity correctness.

### T03 — Attach commits public scene before deferred upload readiness (confirmed ordering; error outcome hypothesis, S0; Q10/CA01/A20)

**Evidence:** `R/renderer.rs:925–1009`: after resources attach and pipelines are ensured, `self.scene = Some(attached)` happens **before** `self.ctx.drain_staging()`; if that returns an error, the function returns Err after publishing the scene. `R/vulkan/passes/corner.rs:129–320` uses deferred batch at end of build; `R/vulkan/context.rs:586–650` refuses a second attach while `corner` exists. `R/vulkan/staging.rs:294–339` explicitly returns timeout or typed Vulkan errors with in-flight work remaining. This is an actual ordering inconsistency; subsequent behavior on timeout/device loss needs reproduction. The CA01 rollback was implemented before R3 and is no longer an end-to-end proof of readiness atomicity.

**Required behavior:** either (a) scene is fully ready and handle published; (b) failure leaves previous usable scene and no reachable partial resource, with retry supported; or (c) typed terminal poisoned renderer state with every device-touching entry refused, no successful scene handle reported, and safe teardown. An upload that is in flight must retain every destination resource until actual completion or a terminal device-loss teardown; a timeout is not completion. Never destroy in-flight destinations on mere timeout. Do not publish first, drain later, or call rollback while dependent pipelines still retain destroyed resources.

**Fix:** `PreparedScene` RAII transaction owns temporary resources, dependent pipeline group and upload ticket; commit only when actual upload readiness and all validation succeed. Failure before submission drops immediately; submitted failure moves resources into a quarantine/retirement list tied to the ticket or terminal device state. If deferred async API is intentionally exposed, return `PendingScene` not a ready `SceneHandle`, and prohibit frame reference until ready. Reuse the same ownership mechanism in context, attach and future replacement. Audit `release_staged_scene_resources` fallback `device_wait_idle().ok()`; distinguish device lost and other idle failures instead of assuming success. Test R3 `StagingFenceNeverSignals` during attach, then inspect `scene()`, attempt submit and attach retry, and verify handles and validation. Inject every pipeline group and staging allocation/submit/fence error. First-render and later-render variants.

### T04 — Dynamic geometry still violates owner complete-primitive admission (confirmed, S0 owner contract; A11/F03/D-EE-10 §1E)

**Evidence:** `R/config.rs:424–453` states explicitly that overflow can cut a 36-vertex proxy box mid-primitive; `dynamic_geometry_clamp` uses `supplied.min(capacity)`. `R/vulkan/uploads.rs:29–60` allocates vertex counts to two layers using raw lengths and copies exactly that count. `R/vulkan/frame.rs:1315–1380` uses that policy for region and overlays. Compute one admission plan before upload; partition foreground and world by complete units with deterministic order, report requested/admitted/omitted vertices AND units, capacity, reason, growth/refusal. ### T05 — Raw caller generations are not robust identity/shape contracts (confirmed implementation, strong correctness hypothesis, S0/S1; A18)

**Evidence:** `R/proxy_instances.rs:399–453` caches by `u64 generation` plus total byte length; `R/animation.rs:738–791` same for pose blocks; `R/submission.rs:295–334,385–493` verifies reused concatenated bytes only in debug/test, while per-kind counts are taken anew. `R/vulkan/frame.rs:1404–1479` slot and indirect gates compare bare generation. Current demo `S/corner_demo.rs:226,302,334–439` starts at 1 and bumps local counters. Even identical concatenated bytes with different NPC/vehicle/rain partitions can produce different indirect counts; a byte-only oracle cannot detect every shape change. The public docs may require globally unique generation values for the renderer lifetime; if so, demonstrate how a consumer actually guarantees that invariant and make misuse unrepresentable or fail-visible. Do not label a documented invalid use a reproduced engine bug without verifying the contract.

**Fix:** owned or borrowed versioned population resource with an engine-assigned producer/resource identity, monotonically increasing revision (wrap/renewal policy), separately keyed instance/pose/indirect shape and frame allocation epoch. A simple renderer-owned `PopulationHandle` with revision-scoped snapshots and stable shape may suffice. For always-dirty external slices keep zero-generation safe fallback; do not make callers responsible for hidden global identity conventions. Separate indirect-count identity from payload identity; include per-kind counts and draw shape. Validate pose indices when trusted resource is constructed/changed, not every unchanged frame. Compare against independent full-repack and GPU readback in release, not only debug. Test independent sources at same local version, same-total/different-kind partition, mode switching, generation wrap/reset, rejected submission followed by retry, resource replacement, frame-slot ping-pong, and same-generation mutation. Acceptance is correct pixels AND correct indirect command bytes/counts, no stale skip.

### T06 — Error disposition can lose terminal device state and leave unusable frame slots (confirmed latch gap; WSI hypothesis, S0; CA10/CA13/A14)

**Evidence:** `R/vulkan.rs:330–372` DeviceLossLatch observes only top-level DeviceLost or `FrameSlotUnrecoverable.source` if DeviceLost; ignores the `release` error. `R/vulkan/frame.rs:1162–1290` creates FrameSlotUnrecoverable on cleanup failure, and generic present failure marks semaphore untrusted but can retain acquired image; resets command buffer best-effort, uses `get_fence_status(...).unwrap_or(false)`, then potentially submits a heal. Public frame entry gates use device-loss latch; non-device-loss terminal slot error is not evidently permanently latched. Additionally direct present of an acquired but unrendered image assumes it is presentable; a newly created never-rendered swapchain image has no established PRESENT layout. The source comments call acquire an implicit layout transition; validate that premise against Vulkan WSI and actual validation evidence rather than trusting the comment. First-use vs previously-presented image must be distinguished. A device loss during cleanup is not necessarily the same error as the original failure.

**Fix:** explicit renderer lifecycle enum (Ready, RecreateRequired, Poisoned(reason), DeviceLost(reason), Destroying) with terminal or recovery transitions. On error inspect both original and cleanup error chains, record first device loss at detection, never issue unnecessary further work on lost device. Propagate non-timeout/non-NOT_READY errors rather than convert them to state booleans. On failed acquire-to-submit transaction, guarantee legal semaphore/image disposition: if presenting a previously rendered image, prove layout; for first-use images use a minimal valid transition submit or supported swapchain-maintenance release path, or terminal/recreate policy; do not present undefined layout. Avoid silent pool exhaustion after hard present failure. Track whether submission actually succeeded before resetting command buffer or fence; successful submissions require completion proof. Test all first-frame failure sites, new swapchain first use, arbitrary fault from cleanup rather than source, device lost on poll/wait/submit/present/map, hard present failure, and repeated entry refusals. Real GPU sync and core validation must remain clean. A failed driver call in cleanup may require safe leak/quarantine until device teardown; document exact state.

### T07 — Retention acknowledgment is a permanent assertion, not a safe moving cut (confirmed, S0 for consequence-bearing composition; Q05/CA07)

**Evidence:** `C/spine.rs:385–419` `ConsequenceEligibility::acknowledged()` is an opaque zero-sized Copy assertion; `:2758–2955` sets it once, then automatically compacts each qualifying tick with no per-cut watermark or revocation other than explicit config reset. Update after actual canonical confirmation and consumer retirement, not at configuration time. Model multiple consumers, unknown/indeterminate commit, late readers, blocked/held obligations, host change, checkpoint/recovery, restore config and pending records. Provide explicit lag/backpressure policy; do not discard data to keep RAM under a target. Keep canonical digests byte-equivalent for identical cut sequence; version any changed durable format. Replace tail-shifting vector with measured ring/deque/chunked segments or logical head plus amortized compact when appropriate. Measure total bytes moved, not allocation count only; fixed chunk smaller than sustained arrivals must surface lag and apply admission/backpressure or choose a valid cadence. Explicit compaction API must also respect composition-level eligibility where used. Test unresolved consequence across threshold, advancing safe frontier, refusal, rollback/restore, repeated compaction with identical logical state and authoritative history, sustained arrivals at greater/equal/lower than chunk. Retain manual operator authority and no fabricated proof.

2. **Modularity:** acyclic dependency boundaries, independent core/animation/render types/provider use, renderer not hard-wired to one demo topology, clear provider/shared contracts, no generic framework solely for perceived modularity.
3. **Scalability:** actual admitted work and resident memory proportional to active/changed/local workload, not lifetime history or global world size, bounded construction/admission, explicit overload and lag, real scale measurements including large geometry and historical states.
4. **Maintainability:** enforceable invariants (ownership/version/eligibility/typed errors), transactional resource lifecycle, reliable independent CI, stable public API policy, no stale status/control plane, evidence that future extension is feasible without duplicating mechanisms.
5. **Optimality/efficiency/performance:** matched work/fidelity, eliminated known avoidable copying, scans, allocation, GPU stalls, disproportionate memory and unnecessary work or narrowly justified exceptions, independently verified tradeoffs, no unjustified global idle or retention loss.
6. **Lightweight:** minimal independent dependency closures, optional providers/features without weakened safety, actual release artifact/heap/VRAM/compile costs, no forced native/render stack for pure consumers, avoid excessive retained pool memory.
7. **Speed:** release measured throughput and tail latency for realistic work; actual matched before/after with variability, independent hardware results and clear bottleneck model. No source-only “9” or microbench substituted for whole workload.
8. **Documentation:** accurate API contracts, architecture and current status, explicit design assumptions/limits and owner decisions, reproducible verification/evidence, coverage ledger and correct terminology; no contradiction between docs and source.

**Hard blockers:** unresolved S0 defects/hypotheses without proof, false authority/canonical confirmation, silent durability downgrade, unsafe resource lifecycle, incomplete primitive admission, stale cache causing incorrect frame data, unbounded admitted resource/work without explicit contract, weakened fidelity or test gates, misleading measurements, no exact-head green CI/required rig evidence, unreviewed material source areas. A decision that a hypothesis is refuted must carry the specific reasoning/evidence. An unimplemented design cannot be scored as implemented. Do not lower any gate to achieve a numerical quota.

## 11. Final independent disposition

PostRust has made significant engineering progress. Its core design and the recent P5 and provider work deserve to be preserved. The strict review is not a recommendation for a whole-project restart; there is no evidence that abandoning the existing engine would improve the risk/cost of meeting the requirements. Incremental hardening, targeted subsystem redesign and a few clean package boundaries remain the rational course.

However, the branch is **not ready for final acceptance or mainline integration**. Most urgent concerns are exact-head verification, complete-primitive admission, resource readiness/failure-state composition, resource/cache identity, and safe authoritative retention. Larger structural obligations remain scheduler locality and bounded fan-out, historical active residency, general scene/resource lifetime, genuine sparse dirty work, independent animation/render contracts and actual scaled evidence. Several already “closed” items need precise partial status, not repeated optimistic closure.

Final instruction: continue development autonomously on `refactor/engineering-excellence`; independently adjudicate T01–T40, preserve every proven improvement and owner decision, and satisfy the original charter before P7. The owner remains the sole final mainline integration authority.
